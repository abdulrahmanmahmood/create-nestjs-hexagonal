# nestjs-hexagonal

A professional NestJS project demonstrating Hexagonal Architecture (Ports & Adapters) and Clean Code principles.

## Project Overview

This project implements a user management module using Hexagonal Architecture, also known as Ports and Adapters. The architecture separates business logic from infrastructure and presentation, making the codebase maintainable, testable, and scalable.

### Hexagonal Architecture

- **Domain**: Contains core business logic and entities.
- **Application**: Contains use cases and ports (interfaces for repositories).
- **Infrastructure**: Contains adapters (implementations of ports, e.g., in-memory repository).
- **Presentation**: Contains controllers and API endpoints.

#### Folder Structure

```
eslint.config.mjs
nest-cli.json
package.json
pnpm-lock.yaml
README.md
tsconfig.build.json
tsconfig.json
src/
  app.module.ts
  main.ts
  user/
    user.module.ts
    application/
      ports/
        user.repository.ports.ts
      use-cases/
        create-user.use-case.ts
        get-user.use-case.ts
    domain/
      entities/
        user.entity.ts
      value-objects/
        email.vo.ts
        user-id.vo.ts
    infrastructure/
      adapters/
        in-memory-user.repository.ts
    presentation/
      user.controller.ts
test/
  app.e2e-spec.ts
  jest-e2e.json
```

### Ports & Adapters

- **Ports**: Defined as interfaces in `application/ports`. E.g., `IUserRepository`.
- **Adapters**: Implementations in `infrastructure/adapters`. E.g., `InMemoryUserRepository`.
- **Use Cases**: Application logic in `application/use-cases`. E.g., `CreateUserUseCase`, `GetUserUseCase`.

### Clean Code Principles

- Separation of concerns
- Dependency injection
- Testability
- Explicit interfaces

## Usage

1. Clone the repository
2. Install dependencies: `pnpm install`
3. Run the app: `pnpm start`

## Example

- Create a user: `POST /user`
- Get a user: `GET /user/:id`

## Why Hexagonal Architecture?

- Decouples business logic from frameworks and external systems
- Makes it easy to swap infrastructure (e.g., switch from in-memory to database)
- Facilitates testing and maintainability
